# Internationalization

Driftfield is English-default. Users can switch language in Settings without a
restart. The initial supported languages are `en` and `zh-CN`; add another only
when its complete catalog and tests land together.

Use `i18next` in shared/main code and `react-i18next` in the renderer. Keep both
as direct dependencies. Do not add browser language detection, an HTTP backend,
a translation CDN, or `localStorage` locale state. The versioned main-process
settings file is the source of truth.

## Locale contract and persistence

- Keep `APP_LANGUAGES`, `AppLanguage`, and `AppSettings.language` aligned.
- Keep the current pre-release settings schema exact. Missing, outdated, or
  invalid settings fall back to the English-default settings object. After the
  first public release, incompatible changes require a versioned migration.
- Validate language changes in main; never accept arbitrary locale identifiers.
- Show self-names `English` and `简体中文` in the selector.
- A successful change immediately updates renderer i18next,
  `documentElement.lang`, and `documentElement.dir`.
- Derive direction from i18next for future RTL support.
- Failed persistence leaves the active language unchanged.
- UI language affects application chrome only. Do not translate manuscripts,
  filenames, project/provider/model names, user prompts, or model output.

## Resource ownership

Locale resources are statically imported TypeScript so they are offline,
packaged in ASAR, and type-checked:

```text
src/
├── shared/i18n/
│   ├── languages.ts
│   ├── resources.ts
│   └── locales/
│       ├── en.ts
│       └── zh-CN.ts
├── main/i18n/main-i18n.ts
└── renderer/i18n/index.ts
```

- Organize catalogs by feature namespaces such as `common`, `settings`,
  `library`, `editor`, `assistant`, `projects`, and `errors`.
- Use stable semantic keys, not English source text.
- English is the canonical catalog shape. Other locales must satisfy a deeply
  widened TypeScript shape derived from it.
- Keep interpolation placeholders identical across locales.
- Configure bundled resources with `fallbackLng: 'en'`, explicit supported
  languages, and no missing-key network writes.
- Use i18next interpolation/pluralization and `Intl`; do not concatenate
  translated fragments.

## Renderer behavior

- Bootstrap settings and initialize i18next before the first React render to
  avoid a locale flash.
- On bootstrap failure, initialize with default English and surface the existing
  settings error after mount.
- Components use `useTranslation(namespace)`.
- Non-component helpers receive translated text or a `TFunction`, or return
  stable codes; they do not casually import mutable global translators.
- Translate visible copy, accessibility labels, titles, placeholders, tooltips,
  empty states, statuses, errors, and confirmations.
- Do not translate brand/provider/model names, shortcut glyphs, or user data.
- Feed MDXEditor's `translation` prop from the active editor namespace.
- Reserve `<Trans>` for messages containing React elements; use `t()` for plain
  text.

## Main and IPC

Main owns a separate non-React i18next instance. Native dialogs, pickers,
notifications, and custom menu labels translate using the current persisted
language when displayed. Built-in Electron menu roles retain OS localization.

Do not send localized error prose over IPC. Send typed status/error codes and
serializable interpolation parameters; renderer maps them to catalog keys.
Internal SDK/filesystem exception strings are for logs, not direct display.

Preload exposes no translator, locale resources, generic i18n IPC, or language
mutation outside the validated settings API.

## Catalog changes and tests

- Move visible Chinese literals into `zh-CN` and write reviewed English in `en`.
- Do not leave mixed-language screens or placeholder-quality English.
- Keep developer logs and internal invariant text in English unless deliberately
  mapped to a visible application code.
- Do not localize Agent system prompts through the UI catalog.
- Every visible behavior change updates every supported locale in the same
  change; fallback is not a substitute for a complete catalog.

Cover settings validation, locale and interpolation parity, renderer
switching, document language/direction, main native UI translation, and the
MDXEditor adapter. Retain packaged smoke coverage proving both catalogs are in
ASAR without runtime network fetches.
